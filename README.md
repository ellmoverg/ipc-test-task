# Дизайн
В якості каналу комунікації між процесами було обрано POSIX shared memory, в якій зберігається SPSC циклічний буфер. Оскільки такий канал звʼязку не передбачає ніякої синхронізації зі сторони ядра, цю логіку довелось реалізовувати самостійно ретельним міркуванням про С++ memory model і release/acquire семантику.
Щодо обробки сигналів й інших зовнішніх подій, я вирішив піти шляхом розмежування control і data plane, відтак обробка відбувається в стандартному коді, де немає обмежень як у обробників сигналів (також в control thread вписалось і виведення інформації про отримані пакети)

# Запуск
Розробку я проводив на macOS з процесором ARM64, однак нічого специфічного не використовував, тож має працювати й на інших POSIX сумісних ОС. Збірка як і вимагалось за допомогою CMake, є три targets - producer, consumer та ring_test (юніт тести на мою основну структуру даних). Перші дві включені за замовченням, третю потрібно явно вказати. 
В директорії куди був склонований репозиторій:
```sh
cmake -S . -B ../build # я використовував out of tree builds
cd ../build
cmake --build .

../build/consumer # запускаємо в різних терміналах з producerʼом
../build/producer 262144 # оптимальне корисне навантаження було обрано емпіричним шляхом

cmake --build . --target ring_test
ctest --test-dir . --output-on-failure
# 
```
